# Rakuten MLOps

Local MLOps stack for the Rakuten product classification project.

## Services

The Docker stack is defined in `docker-compose.yml`.

| Service | Role | URL |
| --- | --- | --- |
| `api` | FastAPI service for auth, prediction and training routes | http://localhost:8000 |
| `streamlit` | Demo and control front-end for the whole stack | http://localhost:8501 |
| `mlflow` | MLflow tracking server | http://localhost:5000 |
| `airflow-webserver` | Airflow UI | http://localhost:8080 |
| `airflow-scheduler` | Airflow scheduler | internal |
| `airflow-postgres` | Airflow metadata database | internal |

## Prerequisites

- Docker Desktop running.
- A local `.env` file created from `.env.example`.

## First start

Create the local environment file:

```bash
cp .env.example .env
```

On Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Edit `.env` and set at least:

```env
API_JWT_SECRET=replace-with-a-local-secret
AIRFLOW_WEBSERVER_SECRET_KEY=replace-with-a-local-secret
```

Then build and start the stack:

```bash
docker compose up -d --build
```

## Daily commands

Start services:

```bash
docker compose up -d
```

Stop services:

```bash
docker compose down
```

Rebuild images:

```bash
docker compose build
```

Rebuild and restart:

```bash
docker compose up -d --build
```

Check service status:

```bash
docker compose ps
```

Follow logs:

```bash
docker compose logs -f
```

Follow one service:

```bash
docker compose logs -f api
docker compose logs -f mlflow
docker compose logs -f airflow-webserver
docker compose logs -f airflow-scheduler
```

The same commands are available through Make:

```bash
make docker-build
make docker-up
make docker-down
make docker-logs
```

## Local URLs

- API health: http://localhost:8000/health
- API readiness: http://localhost:8000/ready
- API docs: http://localhost:8000/docs
- MLflow UI: http://localhost:5000
- Airflow UI: http://localhost:8080
- Streamlit front-end: http://localhost:8501

Default local Airflow credentials:

```text
admin / admin
```

These values come from `.env` and can be changed locally.

## API mode

By default, the Docker stack starts the API with:

```env
API_STUB_MODE=true
```

This allows the API container to run without local model artifacts. Prediction
responses are generated by the stub predictor and are only suitable for local
integration checks.

To run real inference, place the required artifacts locally:

```text
core/artifacts/model.keras
core/artifacts/labels_map.json
core/models/artifacts/scaler.joblib
core/models/artifacts/pca.joblib
```

Then set:

```env
API_STUB_MODE=false
```

Restart the API:

```bash
docker compose up -d --build api
```

## Front-end

The Streamlit front-end is the entry point for demos: it walks through the
project, calls the API over HTTP and reports the state of every service.

Run it inside the stack:

```bash
docker compose up -d --build streamlit
```

Or directly on the host, against a locally running API:

```bash
uv sync --group streamlit
make ui
```

Endpoints are configurable at runtime from the sidebar, and every page keeps
working when a service is down. See [`docs/streamlit.md`](./docs/streamlit.md)
for the page-by-page description and the demo walkthrough.

## MLflow

The MLflow service stores metadata and artifacts in Docker volumes:

```text
mlflow_backend
mlflow_artifacts
```

Inside the Docker network, services should use:

```env
MLFLOW_TRACKING_URI=http://mlflow:5000
```

From the host machine, use:

```env
MLFLOW_TRACKING_URI=http://localhost:5000
```

## Airflow

Airflow loads DAGs and plugins from:

```text
services/airflow/dags
services/airflow/plugins
```

The stack runs an `airflow-init` one-shot service that migrates the Airflow
database and creates the local admin user before starting the webserver and
scheduler.

Airflow services receive:

```env
MLFLOW_TRACKING_URI=http://mlflow:5000
RAKUTEN_API_URL=http://api:8000
```

## Environment files

`.env.example` is committed as a template.

`.env` is local only and must not be committed. It contains local secrets,
ports and runtime flags.

## Troubleshooting

If a container name conflict occurs:

```bash
docker compose down --remove-orphans
docker compose up -d
```

If healthchecks are not green:

```bash
docker compose ps
docker compose logs --tail=100 api
docker compose logs --tail=100 mlflow
docker compose logs --tail=100 airflow-webserver
docker compose logs --tail=100 airflow-scheduler
```

If Docker seems stuck during rebuilds, rebuild a single service:

```bash
docker compose build api
docker compose build mlflow
docker compose build airflow-webserver
```

To reset local Docker state for this project, including volumes:

```bash
docker compose down --volumes --remove-orphans
docker compose up -d --build
```
